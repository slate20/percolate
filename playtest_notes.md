## Bugs/Fixes

- ~~Vague text under roasting, eg "Medium Green" "Medium Brown" "Medium Yellow" "Medium Dark". Color label not meant to be shown?~~ Fixed: dropped the internal color-stage key from the footer, and went further — the slot header now shows the full resolved roast name (curated recipe name, or generated "Bean Level Flavor" name) via resolve_roast, so each roaster slot identifies exactly what's in progress at a glance (matters once players have multiple roasters running). Long names now word-wrap onto a second header line instead of clipping (Static doesn't wrap on its own — RoastScreen._wrap_header does it manually), with a blank spacer line before the art; each card auto-sizes to its own content so short and long names both stay tidy.
- ~~Menu/UI navigation is a bit clunky. Mouse interaction is fine but keyboard interaction is not as intuitive as it should be. Tab switching between elements is "Textual" domain knowledge, but not immediatly obvious to players who are non-devs. Pressing enter also makes the highlighted item un-highlight. Pressing an arrow key brings the highlight back, but again not obvious to an average player.~~ Fixed, took two passes. `ListView.clear()` always resets `.index` to `None`, and `MarketScreen.refresh_market()` rebuilds all four lists on every buy/sell — first fix just restored `.index` after rebuilding (matching the pattern `UpgradeModal` already used), but that wasn't enough: `.clear()`/`.append()` are asynchronous (return `AwaitRemove`/`AwaitMount`), so setting `.index` synchronously right after read/wrote against a node list that hadn't actually finished settling — `.index` looked set but Textual's own highlight-painting logic silently skipped it, so the highlight still visually vanished. Real fix: made `refresh_market` (and its callers) properly `async`/`await` the clear+repopulate before touching `.index`, and clamp to the new last row instead of dropping to `None` when the highlighted row itself got sold out and removed. Verified against real keypress simulation, not just direct state checks. Also added an inline "(tab) next field/list (shift+tab) previous" hint to Market and Roast's builder panel, since both rely entirely on Textual's default Tab-cycling focus with no on-screen indication it exists — unlike Farm, which sidesteps this with its own bespoke arrow-key cursor. **Follow-up for a later iteration:** revisit whether Market and Roast should get that same bespoke arrow-key navigation (no Tab dependency at all), so keyboard control feels cohesive and intuitive across the entire app instead of Farm being the only screen with a custom scheme.

**Follow-up, focus/highlight polish (done):** Textual's own default keeps a *dimmed* highlight visible on a list even after it loses focus, rather than clearing it, which read as ambiguous. Added `percolate/focus_widgets.py` (`FocusHighlightListView`/`FocusHighlightOptionList`/`FocusHighlightSelectionList`) so every Tab-cycled list is a clean binary instead: gaining focus auto-highlights the first item, losing focus clears the highlight entirely, Enter within the same pane leaves it alone. Applied to all of Market's lists, UpgradeModal, Roast's bean/flavor/level fields, and Farm's seed-picker modal. Roast's Bean and Roast Level fields are a special case — their highlight is the only visual indicator of a persistent choice (which bean/level the next roast uses), not just a browsing cursor, so on focus they show *that* selection specifically (via `RoastScreen._sync_selection_highlight`, triggered off Textual's `DescendantFocus` event) rather than defaulting to the first item.

## Improvements/New Features

- Contenct expansion. More beans, flavors, and more discoverable recipes.
- Farm ASCII art starts small and grows, visual representation of players progression.
- ~~Add a toggle to hide the plot box yellow outline (for viewing aesthetic)~~ Done: `o` on the Farm screen toggles it. CSS-only — `#field.hide-cursor-outline .plot-cell.cursor` overrides the border back to plain grey, so the cursor/keyboard logic itself is untouched; still gates `(enter)`, just doesn't show the gold border. Not hinted in the header (kept that muted per-screen line uncluttered) — it's covered in the new help guide instead. While implementing, also fixed the plot fade animation: it used to key off the coarse color bucket (empty/early/mid/ready), so it fired on planting and harvesting (unwanted — those are immediate player actions) but *didn't* fire on seed -> sprout (both bucketed as "early", so no visible fade for a real stage change). Now keyed off the actual art stage (seed/sprout/growing/ready) with empty explicitly excluded on either side, so planting/harvesting are instant and every real growth-stage change fades.
- ~~Addition of a new "help/get started" guide screen or modal. Just a markdown viewer widget and a simple brief guide composed in markdown~~ Done: `h` (global, from any screen) opens `HelpModal`, a `VerticalScroll` + Textual's `Markdown` widget over static copy in `data/help_guide.md`. Covers per-screen controls (including the outline toggle) and how curated-recipe discovery works. `h` also closes it again, mirroring the open key, and `escape` works too.
- Partial content expansion: added 5 new curated recipes (`data/recipes.json`) using the chocolate/hazelnut flavors added since the original 4 recipes were written — those two ingredients had no curated recipe at all before this. Recipe count went 4 -> 9, spanning all three beans and all three roast levels, with bonus multipliers/final values kept in the same progressive-value-curve style as the originals (cheaper bean+ingredient combos get a bigger multiplier so they stay worth discovering; geisha combos are priciest by virtue of the bean alone). New beans/ingredients themselves are still open — that's a bigger v2-scope content pass, not a quick tweak.
